# デキレーレット 機能仕様書

Web 版（https://roulette.basekeita.com/）の機能を、実装から洗い出してまとめた仕様書。
iOS 版はこの仕様を元に移植しており、プラットフォーム差分は末尾の「iOS 版との対応」に記す。

- Web 版の対象リビジョン: b7b3936（このリポジトリの履歴に残っている。Web 版のコードは iOS 版への移行時に削除した）
- 数値の定義元: `src/config.ts`、配色の定義元: `tailwind.config.ts`、文言の定義元: `src/i18n.ts`

---

## 1. 概要

### 1.1 コンセプト

「ルーレットで決めたことにしたい」場面で使う抽選ツール。回す前に当てたい項目を仕込んでおくと、
見た目はランダムに回りながら結果はその項目に止まる。人に画面を見せながら使う前提のため、
**仕込めることが画面上から一切分からない**ことを最優先の設計要件とする（§6）。

### 1.2 画面

| 画面 | 役割 | 日本語 URL | 英語 URL |
|---|---|---|---|
| ルーレット | 項目から 1 つを選ぶ | `/` | `/en/` |
| 順番決め | 項目をランダムに並べ替える | `/order/` | `/en/order/` |

2 画面は独立しており、項目リストや指定は共有しない。

### 1.3 非機能

- 状態は永続化しない。リロードすると初期項目に戻る。（iOS 版は項目リストだけ端末に保存する。§12）
- ネットワーク通信は行わない。外部スクリプトも読み込まない。
- ログイン・登録・課金は無い。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 項目 (Item) | ユーザが登録するラベル付きの要素。`id` と `label` を持つ |
| 印 (Mark) | 項目リストの行に出す指定の状態。`target`（当たり）/ `first`（先頭）/ `last`（末尾） |
| 当たり指定 | ルーレットで次のスピンの結果にする項目の指定 |
| 先頭・末尾指定 | 順番決めで 1 位・最下位にする項目の指定 |
| 演出中 (busy) | スピン中、または並べ替え結果を 1 件ずつ出している間 |
| 伏せる (conceal) | 印を無条件に非表示にすること |

## 3. 定数一覧

| 定数 | 値 | 用途 |
|---|---|---|
| `MIN_ITEMS` | 2 | スピン／並べ替えに必要な最小項目数 |
| `MAX_ITEMS` | 24 | 項目数の上限 |
| `MAX_LABEL_LENGTH` | 20 | ラベルの最大文字数（正規化後） |
| `SPIN_DURATION_MS` | 4500 | スピンの回転時間 |
| `SPIN_EASING` | `cubic-bezier(0.15, 0.85, 0.3, 1)` | 回転のイージング（減速して止まる） |
| `SPIN_FALLBACK_MS` | 5100 | 完了イベントが来ない場合に強制終了するまでの時間 |
| `REDUCED_MOTION_SPIN_MS` | 320 | 視差効果を減らす設定時のスピン完了までの時間 |
| `LONG_PRESS_MS` | 600 | 隠しジェスチャの長押し判定時間 |
| `TARGET_HINT_MS` | 1600 | 指定直後に印を見せる時間 |
| `ORDER_REVEAL_STEP_MS` | 160 | 順番の結果を 1 件ずつ出す間隔 |
| `REVEAL_ANIM_MS` | 360 | 結果 1 件が現れるアニメーションの長さ |
| `REDUCED_MOTION_REVEAL_MS` | 200 | 視差効果を減らす設定時の並べ替え演出の長さ |
| `COPY_FEEDBACK_MS` | 1800 | 「コピーしました」を表示する時間 |
| `UNDO_MS` | 5000 | iOS 版のみ。削除を「元に戻す」で取り消せる時間（§4.3） |
| `SLICE_COLORS` | 10 色 | スライスと色見本の配色（§9） |

## 4. 共通機能: 項目リスト

両画面で共有する。見出し「項目」と件数 `現在数 / 24` を右上に表示する。

### 4.1 初期項目

| 画面 | 日本語 | 英語 |
|---|---|---|
| ルーレット | ラーメン、カレー、寿司、焼肉 | Pizza, Burger, Sushi, Tacos |
| 順番決め | A チーム、B チーム、C チーム、D チーム | Team A, Team B, Team C, Team D |

### 4.2 追加

- 入力欄と「追加」ボタン。Enter キー（フォーム送信）でも追加できる。
- 入力欄は `maxLength=20`。
- 追加時にラベルを**正規化**する: 連続する空白（改行含む）を半角スペース 1 つに潰し、前後の空白を落とし、先頭 20 文字で切る。
- 正規化後が空文字なら追加しない。
- 項目数が上限 (24) に達している間は、入力欄と追加ボタンを無効化し、「項目は 24 個までです」を表示する。
- 演出中は入力欄と追加ボタンを無効化する。
- 追加すると表示中の結果を消す（ルーレット: 結果ラベル、順番決め: 結果リスト）。iOS 版のルーレットは結果の帯と盤面の強調を消す（§5.3）。
- 項目 ID はランダム（`crypto.randomUUID`、非 secure context では時刻＋乱数）。同じラベルの重複登録は許す。
- iOS 版のみ: 入力に改行が含まれていれば行ごとに正規化して空行を除き、まとめて追加する（一括追加）。
  - 20 文字の制限は行ごとに掛ける。1 件ずつの正規化の規則は変えない。
  - 複数行が入っているときは追加ボタンの表示を「N 件追加」にする。
  - 上限 (24) を超える分は切り捨て、「項目は 24 個までです」で伝える（VoiceOver には同じ文言を読み上げる）。
  - 追加したあとも入力欄のフォーカスを保ち、続けて次の項目を入力できる。キーボードは下スワイプで閉じる。
  - 「使い方」の基本操作に、改行区切りで貼り付けるとまとめて追加できる旨を載せる。
  - 入力欄のプレースホルダーでも「項目を入力（改行で複数追加）」/ "Add items (one per line)" と示す。
- iOS 版のみ: 同じラベルの項目があるときは**警告だけ**を出す。追加・スピン・並べ替えは止めず、同名の項目を自動で消したりまとめたりしない。
  両画面で同じ規則・同じ見た目で、画面ごとの切り替えは持たない。
  - 「同名」は正規化後のラベルの完全一致。大文字小文字・全角半角の違いは別物として扱う。
  - リスト上の注意: 同名の項目がある行すべてのラベルの下に「⚠ 同じ名前の項目があります」/ "Duplicate name" を出す（補助テキストの色）。
    項目から毎回求めるので、1 件追加・一括追加・保存したリストの読み込み・保存データの復元・「元に戻す」のどの経路で入っても出て、
    消すか名前を変えるまで出たまま。演出中・結果表示中も出す。行の読み上げにも含める。
  - 追加時の確認: 追加するラベルが既存の項目と同名、または一括追加の行同士で同名なら、追加の前に
    「同じ名前の項目があります／このまま追加しますか？」を出す。「追加する」で同名の行も除かずに通常の追加と同じく追加し（上限 (24) を超える分は切り捨てる）、「やめる」で何も追加せず
    入力を残してフォーカスを戻す（Return で送信したときの末尾の改行は落とす）。同名でなければ確認なしで追加する。
    読み込み・復元・「元に戻す」では確認を出さない（リスト上の注意だけで伝える）。
  - 指定（§6）とは無関係に出す。同名の片方に指定が付いていても、注意の見た目・読み上げは同名の行すべてで同じにし、
    印（色見本）の位置・形・色は変えない。文言に「当たり」等の語は置かない。

### 4.3 削除

- 各行右端の「✕」ボタン。読み上げ名は「{ラベル} を削除」。
- 演出中は無効化する。
- 削除した項目に指定（当たり／先頭／末尾）が付いていれば、その指定も外す。
- 削除すると表示中の結果を消す。
- iOS 版のみ: 見出し行に「すべて削除」を置き、確認ダイアログを経て全件削除する。項目 0 件と演出中は出さない。指定と結果も消える。
- iOS 版のみ: 行を左にスワイプすると、右端に「削除」ボタンが現れる。押すと「✕」と同じく削除する。
  - 指が 20pt（`Config.swipeMinimumDistance`）動き、その時点で横が優勢なときだけスワイプとして扱う。縦や斜めはスクロールに譲る。
  - 行幅の半分（`Config.swipeDeleteRatio`）を越えて引いたら、指を離した時点でそのまま削除する。勢いだけでは削除しない。
    それ未満なら、離した勢いを足した位置が削除ボタンの半分を越えれば開いたまま止め、越えなければ閉じる。
  - 開いておくのは常に 1 行だけ。開いた行のタップで閉じる。演出が始まったら閉じ、演出中はスワイプできない。
  - 長押し（§6.1）は指が 10pt 動くと不成立になるので、スワイプしようとして指定することはない。長押しで指定が成立したあとに
    指を動かしても、その操作ではスワイプを始めない。削除ボタンの見た目は指定の有無で変えない。
  - 削除ボタンは読み上げから外す（VoiceOver では「✕」で同じ操作ができる）。`accessibilityAction` は置かない。
- iOS 版のみ: 「✕」かスワイプで削除した直後の 5 秒間、リストの下に「{ラベル} を削除しました　元に戻す」を出す。
  - 「元に戻す」で同じ `id` の項目を元の位置に戻す。指定（当たり／先頭／末尾）は復元しない。戻すと表示中の結果は消える。
  - スピン／並べ替えを始めたら閉じて取り消し不可にする。表示中に別の項目を削除したら直前の削除は確定して置き換える（多段 Undo は持たない）。
  - 元の位置が項目数を超えていれば末尾に戻す。同じ項目がすでにあるか上限 (24) に達していれば何もしない。
  - 表示と同じ文言を読み上げる（`aria-live` 相当）。文言に「当たり」等の語は置かない。

### 4.4 行の表示

- 左に 12px の丸い**色見本**（項目の並び順 i に対し `SLICE_COLORS[i % 10]`）、右にラベル（1 行、はみ出しは省略記号）。
- 色見本はルーレットのスライス色と一致する。順番決めにも同じ色を使う。
  iOS 版は件数によって末尾の色をずらす（§5.1、§12）。色見本も盤面と同じ関数で引くので、ずらした色でも一致する。
- 行本体はボタン要素で、隠しジェスチャ（§6）の受け口。単純クリック／タップでは何も起きない。
- リストは最大高さ 320px でスクロールする。

### 4.5 状態メッセージ

| 条件 | 表示 |
|---|---|
| 項目 0 件 | 破線枠で「まずは項目を追加してください」 |
| 項目 1 件以下 | 赤字で「項目をあと少なくとも 2 つ追加してください」 |
| 24 件 | 「項目は 24 個までです」 |

### 4.6 名前を付けて保存したリスト（iOS 版のみ）

Web 版には無い。用途ごとの項目リスト（ランチの候補、チームのメンバー…）を名前を付けて保存し、呼び出せる。

- 見出し行の右端にメニュー（`…`）を置く。「このリストを保存」「保存したリストから読み込む」（保存済みの一覧をサブメニューで出す。無ければ「保存したリストはありません」）「保存したリストの管理」の 3 つ。行本体のタップ・長押しの挙動（§6）は変えない。演出中はメニューを無効化する。
- 保存: 名前を入力するアラート（テキスト欄付き）を出す。名前は項目のラベルと同じ規則で空白を潰し、30 文字で切る。空なら保存しない（保存ボタンを無効化）。項目が 0 件のときは保存を選べない。
- 保存できるのは 20 セットまで。上限に達した状態で保存を選ぶと、管理画面から削除するよう案内するアラートだけを出す。
- 読み込み: 現在の項目を保存したリストの項目で置き換え、表示中の結果と当たり・先頭・末尾の指定を消す。確認は挟まない。
- 保存先はルーレットと順番決めで共通。片方で保存したリストをもう片方で読み込める。
- 保存するのは各リストの `id`・名前と、項目の `id`・`label` だけ。当たり・先頭・末尾の指定は保存にも読み込みにも含めない。
- 管理画面（シート）: 保存したリストを名前と件数で一覧し、行をタップして名前を変更、スワイプまたは「編集」で削除する。読み込みは置かない。
- 永続化は `UserDefaults`（キー `savedLists`）に JSON で保存する。読めないときは空として扱う。読めたリストは名前を正規化し、名前が空・`id` が重複するものは落とし、項目は §4.2 と同じ規則で整える。

## 5. ルーレット画面

### 5.1 盤面

- 320px（画面幅の 78% を上限）の正方形 SVG。中央固定の針（赤い下向き三角）が盤面の真上 (12 時) にある。
- 項目 i のスライスは角度 `[i·360/n, (i+1)·360/n)` を占め、12 時から**時計回り**に並ぶ。
- スライスの塗りは `SLICE_COLORS[i % 10]`、区切り線とラベルは地色 `#17111F`。
  盤面は環なので末尾のスライスは先頭と隣り合い、件数 n が `n % 10 == 1`（11 件・21 件）のときは継ぎ目が同じ色になる。
  iOS 版はこの件数のときだけ末尾の色をずらす（§12）。
- ラベルは半径の 62% の位置に放射方向に置き、左半分は 180 度返して上下逆さまにならないようにする。
- ラベルは項目数に応じて省略する:

| 項目数 | 最大表示文字数 | フォントサイズ |
|---|---|---|
| 〜5 | 10 | 13 |
| 6〜8 | 7 | 11 |
| 9〜 | 5 | 9 |

- 項目 0 件: 無地の円盤。1 件: 全面 1 色にラベルを中央表示（スピンは不可）。
- 中央にハブ（暗色の円＋アイボリーの縁と芯）。
- iOS 版は横並び（`horizontalSizeClass == .regular`、主に iPad）で盤面を最大 480pt に広げる。線幅・縁・ハブは直径に比例させ、
  上の表の文字数と文字サイズは直径 320pt を基準に、それより大きい盤面では倍率の平方根ずつ緩める（§12）。

### 5.2 スピン

- 「スピン」ボタン。項目が 2 件以上かつスピン中でないときだけ有効。スピン中はラベルが「スピン中…」になる。
- 押した瞬間にフッターの「使い方」を自動的に閉じる（§6.4）。
- 回転角の計算（`useRoulette.spin`）:
  1. 当たり指定があればその項目の添字、無ければ一様乱数で添字を選ぶ。
  2. そのスライス内のランダムな角度 `raw` を決める。
  3. 針の下に来る盤面角は `(360 − R) mod 360` なので、`raw` に止めるための目標剰余 `desired = (360 − raw) mod 360` を求める。
  4. 現在の回転角との差 `delta` を 0〜360 で求め、10 度未満なら 1 周足す（ほとんど動かないスピンを避ける）。
  5. 周回数を 4〜8 周から乱数で選び、`next = current + 周回数·360 + delta` を累積回転角とする。
- 回転は CSS `transform: rotate()` のトランジション（4.5 秒、`SPIN_EASING`）。累積角を使うので常に同じ方向（時計回り）に回る。
- 完了は `transitionend` で検知する。バックグラウンドタブ等で発火しないときは 5.1 秒のタイマーで打ち切る。
- 結果はスピン開始時に確定しており（`pendingResult`）、完了時に表示する。
- iOS 版は盤面のフリックでも開始できる。フリックの強さは手順 5 の周回数にだけ反映し、止まる位置の計算は変えない（§12）。
  フリックした向きに回し、反時計回りでは手順 4 の `delta` を逆向きに測って `next = current − 周回数·360 − delta` とする（累積角が減る）。
  「スピン」ボタンは直前のフリックの向きで回す（§12）。ドラッグ中は盤面が指に追従し、指を離した角度を `current` としてスピンを始める（§12）。
  盤面は指を離した瞬間の速さで回り出し、そこから減速する（曲線の始点の傾きだけを変え、長さと止まる位置は同じ。§12）。

### 5.3 結果表示

- 盤面の下、高さ固定の領域に表示する。
  - 未スピン: 「スピンすると、ここに結果が出ます」
  - スピン中: 「スピン中…」
  - 完了後: 金色 (`gold`) の枠でラベルを強調表示。`animate-reveal` で現れる。
- 領域は `role="status" aria-live="polite"`。スクリーンリーダーには「結果は {ラベル} です」相当が伝わる。
- 項目の追加・削除・指定の変更で結果は消える。
- iOS 版は盤面の下の結果領域を持たない（未スピン・スピン中の案内も出さない。スピン中はボタンのラベルが「スピン中…」になる）。結果は下記の盤面の中心より下に重ねる帯と盤面の強調で見せ、読み上げは従来どおり「結果は {ラベル} です」をアナウンスする（§12）。
- iOS 版のみ: 結果があり演出が終わった後だけ、スピンボタンの下に「結果をコピー」と「共有」を出す（§7.3 と同じ見た目・同じ扱い）。
  - コピーは `結果: {ラベル}` の 1 行。成功したら 1.8 秒間ラベルを「コピーしました」に変える。
  - 共有は共有シート（`ShareLink`）に、コピーの本文に空行を挟んでアプリ名を 1 行足した本文を渡す:
    ```
    結果: ラーメン

    デキレーレット
    ```
  - iOS 版のみ: 共有シートには本文と一緒に結果の画像（PNG、1080×1080 px の正方形）を渡す。画像を本体にし本文を添えるので、X・LINE には画像と本文、Instagram には画像が届く。
    画像には 2D の盤面（止まったスライスの強調と針を含む）・結果の帯・アプリ名の文字だけを描く。項目リスト・印・指定の有無は載せず、「当たり」「必ず」等の語も置かない（§6.5）。
    画面のスクリーンショットではなく描き直すので、画面キャプチャ中に印を伏せる仕組み（§6.3）とは関わらない。3D 表示（§12）が ON でも 2D の盤面で描く。
    地は外観に依らず固定のダーク、アプリ名は白系の文字だけ（アイコンは置かない）。画像は結果が出て演出が終わった後に 1 回だけ描き、スピン中・結果が無いときは作らない。
    画像を作れなかったときは本文だけを共有する。
  - スピン中と結果が無いときはどちらも出さない。
- iOS 版は盤面上で針の下のスライスを強調する。結果が消えると強調も解ける（§12）。
- iOS 版のみ: 結果があり演出が終わった後だけ、盤面の中心より下（下半分）に帯を重ねて結果のラベルを全文で大きく出す（盤面のラベルは §5.1 の文字数で省略されるが、帯は `Config.maxLabelLength` まで省略しない）。結果の文字はこの 1 か所だけで、針の下には出さない。止まった位置は盤面の強調と帯の枠の色で示す。
  - 帯は回転しない層に置き、盤面が回っても指で動かしても文字は回らない。盤面・ハブ・止まったスライスより手前に描き、下半分のスライスとラベルを一部隠す。
  - 白系の地（`Theme.resultBandFill`）に盤面と同じ暗い文字（`resultBandInk`、4.5:1 以上）で、枠は止まったスライスの塗り（`sliceColor(at:count:)`）。`gold` / `flare` は使わない。
  - 寸法は `ResultBand`。盤面と同じく装飾扱いで Dynamic Type には追従せず、直径に比例させる（基準 320pt で 28pt、幅は直径の 72% まで）。収まらないときは 1 行のまま 0.5 倍まで縮め、それでも収まらなければ末尾を省略する。帯の中心は盤面の中心から半径の 40% 下に置き、中心のハブと重ねず、盤面のスライスの円からはみ出さない。
  - 出し直しはスピンごとで、`animate-reveal` 相当で現れる（`accessibilityReduceMotion` ではすぐ出す）。指で盤面を動かしても出し直さない。スピン中と結果が無いときは出さない。
  - 帯は読み上げない（盤面と同じく `accessibilityHidden`）。結果は従来どおり読み上げで伝える。盤面のフリックを妨げないよう触れられない。

### 5.4 当たり指定

- 行の長押し（§6.1）で、その項目を次のスピンの結果にする。もう一度長押しすると解除。
- 同時に指定できるのは 1 項目。別の項目を長押しすると指定が移る。
- 指定は何度スピンしても残る（解除されるまで毎回同じ結果になる）。
- 何も指定していないとき、結果は一様乱数。

## 6. 隠し操作（ステルス）の仕様

以下は仕様であり、削ったり戻したりしない。

### 6.1 ジェスチャ

- 指定は行本体の**長押し (600ms) のみ**。専用ボタン・ツールチップ・メニューは置かない。
- ポインタ: `pointerdown` から 600ms 押し続けたら発火。`pointerup` / `pointerleave` / `pointercancel` で取り消し。
- キーボード: 行にフォーカスして Enter またはスペースを押し続け、OS のキーリピート (`KeyboardEvent.repeat`) が始まった最初のイベントで 1 回だけ発火。単押しでは反応しない。
- 長押し中のコンテキストメニュー・テキスト選択のコールアウト (`-webkit-touch-callout`) は抑止する。
- 演出中は長押しを受け付けない。

### 6.2 印の見え方

- 指定中の行は色見本の**塗りを抜いてリング**（内側 2px の枝）にするだけ。位置・大きさは変えない。
- 末尾指定 (`last`) だけ、リングの中心に 2px の点を置いて先頭と見分けられるようにする。
- 指定中の行は枠線が 1 段明るくなる（`ink-700` → `ink-500`）。
- 印に専用色は使わず、その行の色見本の色をそのまま使う。

### 6.3 印を出す条件

印は次の**すべて**を満たすときだけ表示する。

1. 伏せていない（`concealMarks` が偽）。
   - ルーレット: スピン中は伏せる。
   - 順番決め: 並べ替え中と**結果表示中**は伏せる。
2. 次のいずれか:
   - リストにポインタが乗っている、またはリスト内の要素がフォーカスを持っている。
   - 長押しで指定を変えた直後 1.6 秒以内。
3. iOS 版のみ: 画面がキャプチャ（画面収録・AirPlay ミラーリング・QuickTime への出力）されていない。
   - キャプチャ中は押していても指定直後でも印を出さない。長押しによる指定の切り替え自体は動く（印が見えないだけで、操作は通る）。
   - キャプチャ中であることは画面本文に表示しない。説明は「使い方」の隠し操作の項にだけ置く（§12）。

印を伏せている行では `aria-pressed` を付けず、先頭／末尾のスクリーンリーダー向けラベルも出さない。DOM やアクセシビリティツリーに指定先が残らないようにする。

### 6.4 説明の自動閉じ

- 隠し操作の説明はフッターの「使い方」折りたたみ内にのみ置く。
- スピン／並べ替えを開始した瞬間に、開いていた「使い方」を閉じる。

### 6.5 文言の制約

- 画面本文（折りたたみの外）と meta 情報には「当たり」「必ず」など、仕込みの内容を示唆する語を置かない。
- 英語版の `<title>` / `<h1>` は一般語 (Roulette / Random Order) のみ。ブランド名「デキレーレット」は日本語版の `<title>` / `<h1>` と、英語版の description / JSON-LD `alternateName` にだけ置く。

## 7. 順番決め画面

### 7.1 並べ替え

- 「並べ替え」ボタン。項目が 2 件以上かつ演出中でないときだけ有効。演出中はラベルが「並べ替え中…」。
- 押した瞬間に「使い方」を自動的に閉じる。
- 並び順の決定（`shuffle.arrange`）:
  1. Fisher-Yates で一様にシャッフルする。乱数は `crypto.getRandomValues`。剰余の偏りを避けるため、範囲を割り切れる上限を超えた値は捨てて引き直す。
  2. 先頭指定があれば、その項目を添字 0 の項目と入れ替える。
  3. 末尾指定があれば、その項目を最後の項目と入れ替える。
- 「条件を満たすまで引き直す」方式は採らない（指定以外の並びに偏りが出るため）。指定以外の並びは常に一様。

### 7.2 結果表示

- 結果は順位付きリスト。1 位は金色 (`gold`) の枠と文字、以降は通常色。順位は等幅数字で右寄せ。読み上げは「{n} 番目」。
- 各行は `animate-reveal` に `index × 160ms` の遅延を掛けて 1 件ずつ現れる。全件そろうまで先の順位が読めないようにするための演出。
- 演出中 (`revealing`) は `(n − 1) × 160 + 360` ms 続く。この間は並べ替えボタン・追加・削除・長押しを無効化する。
- 未並べ替え時は破線枠で「並べ替えると、ここに順番が出ます」。演出開始直後で結果が無い状態は「並べ替え中…」。
- 領域は `role="status" aria-live="polite"`。
- 項目の追加・削除・指定の変更で結果は消える。

### 7.3 結果のコピー

- 結果があり演出が終わった後だけ「結果をコピー」ボタンを表示する。
- クリップボードに次の形式で書き込む（改行区切り）:
  ```
  1. A チーム
  2. C チーム
  3. B チーム
  ```
- 成功したら 1.8 秒間ラベルを「コピーしました」に変える。失敗（権限拒否等）したら何も変えない。
- 並べ替え直すと「コピーしました」はリセットされる（どの結果をコピーしたかで判定する）。
- iOS 版のみ: 「結果をコピー」の隣に「共有」を置き、共有シート（`ShareLink`）にコピーの本文に空行を挟んでアプリ名を 1 行足した本文を渡す:
  ```
  1. A チーム
  2. C チーム
  3. B チーム

  デキレーレット
  ```
- iOS 版のみ: 共有シートには本文と一緒に結果の画像（PNG、1080×1080 px の正方形）を渡す（§5.3 と同じ経路・同じ扱い）。
  画像には順位のカード（本文と同じ「1. ラベル」の並び。1 位は `gold`、他は本文の色）とアプリ名の文字だけを描く。行は 10 行まで置き、超えるときは 9 件を並べて最後の行を「ほか M 件」にする。長いラベルは末尾を省略する。
  項目リスト・印・先頭・末尾の指定は載せない。画像は結果が出て演出が終わった後に 1 回だけ描き、並べ替え直すと作り直す。画像を作れなかったときは本文だけを共有する。
- コピー・共有する本文と画像には結果の並びとアプリ名だけを載せ、「当たり」「必ず」等の語や指定の有無を示す情報は含めない（§6.5）。

### 7.4 先頭・末尾指定

- 行の長押しのたびに **先頭 → 末尾 → 解除** と切り替わる。
  - 未指定の項目を長押し: その項目が先頭になる。すでに別の先頭があれば、その指定は外れる。
  - 先頭の項目を長押し: 先頭が外れ、その項目が末尾になる。すでに別の末尾があれば、その指定は外れる。
  - 末尾の項目を長押し: 末尾が外れる。
- 先頭と末尾はそれぞれ 1 項目まで。同じ項目が両方になることはない。
- 印の見え方・伏せ方はルーレットと同じ（§6.2, §6.3）。結果表示中も伏せる。

## 10. アクセシビリティとモーション

- `prefers-reduced-motion: reduce` のとき:
  - すべてのアニメーション／トランジションを実質 0 にする。
  - スピンは 320ms 後に完了扱いにする。
  - 順番の結果は遅延なしに一度に出し、演出は 200ms で終わる。
- 結果領域は `aria-live="polite"`。
- スピン中のボタンは `aria-busy`。
- 削除ボタンに「{ラベル} を削除」の読み上げ名。
- フォーカスリングは `gold` 2px。
- 指定中の行は、印が見えているときだけ `aria-pressed="true"` と先頭／末尾のテキストを付ける（§6.3）。
- iOS 版は触覚フィードバックを持つ（§12）。`accessibilityReduceMotion` のときはスピン中と順番決めの連続的な触覚を鳴らさず、開始と結果だけにする（指で盤面を動かしている間の境目は鳴らす）。
- iOS 版の 3D 表示（§12）は、`accessibilityReduceMotion` のとき盤を傾けず揺らさない（正面に置き、端末の姿勢も読まない）。停止時の押し出しと針の跳ねも 2D と同じく省く。

iOS 版は Dynamic Type（文字サイズ）にも追従する（Web 版はブラウザの文字サイズ設定に依る）。詳細は §12。

- 文字はすべてテキストスタイル（`.largeTitle` / `.body` など）か `@ScaledMetric` で指定し、固定 pt を使わない。盤面（§5.1）だけは装飾として例外で、追従させない。結果は盤面の中心より下に重ねる帯（§5.3）と読み上げで伝える。帯は盤面の一部として盤面の直径に比例させ、文字サイズの設定には追従させない（大きな文字の利用者には、読み上げと「結果をコピー」「共有」で全文を渡す）。
- タッチ領域は 44×44pt 以上（削除ボタンは見た目を変えず押せる範囲だけ広げる）。
- アクセシビリティサイズ（`accessibility1` 以上）では、項目リストと順番の結果行のラベルを 2 行まで許し、順番決めのコピーボタン（§7.3）の固定高さを最小高さに緩める（ルーレットのコピーボタンは 1 行の固定高さのまま）。
- 項目リストの追加フォーム（§4.2）は、入力欄に十分な幅を確保できないとき（大きい文字や狭い画面）に縦積みにする。
- 印（§6.2）の 12pt とリングの線幅 2pt は文字サイズに依らず変えない（大きくすると印が目立つ）。

## 11. Web 固有の仕様

iOS 版には対応物が無い、または OS が代替する項目。

### 11.1 言語と URL

- 表示言語もページも **URL だけ**で決まる (`localeFromPath` / `pageFromPath`)。`navigator.language` は表示の決定に使わない。
- 各ページは自身への `canonical` と `ja` / `en` / `x-default` の `hreflang` を持つ。`x-default` は日本語版。
- 言語やページを増やすときの変更箇所: `i18n.ts` (`LOCALES` / `PAGE_PATHS` / `translations` / `PAGES` / `pageFromPath`)、エントリ HTML、`vite.config.ts` の `input`、各ページの `hreflang`、`public/sitemap.xml`、`scripts/prerender.mjs` の `PAGES`。

### 11.2 プリレンダリング

- ビルド時に React を静的 HTML へ焼き込み、`#root` に入れる。JS 実行前から画面のテキストが HTML にある。
- 焼き込むのは画面に出ている文言だけ。`details` は閉じたまま、`aria-pressed` も出力に含めない。
- 誘導リンク (`LocaleNotice`) はマウント後に描画する。
- `main.tsx` は `#root` の中身の有無で hydrate と初回描画を選ぶ。

### 11.3 SEO・メタ情報

| ページ | `<title>` | `<h1>` |
|---|---|---|
| `/` | デキレーレット｜無料で使えるインチキルーレットアプリ | デキレーレット |
| `/order/` | 順番決め｜無料のランダム並べ替えツール｜デキレーレット | 順番決め |
| `/en/` | 一般語のみ（Roulette / Free） | Roulette |
| `/en/order/` | 一般語のみ（Random Order / Free） | Random Order |

- OGP / Twitter カード、JSON-LD (`WebApplication`)。`public/og.png` は盤面だけの中立な絵。
- `public/robots.txt` / `public/sitemap.xml`（4 URL、`xhtml:link` で言語対応）。

### 11.4 セキュリティヘッダ

`public/_headers` に CSP 等を定義し、Cloudflare の静的アセット配信が適用する。外部スクリプト追加時は `script-src` / `connect-src` を更新する。

### 11.5 デプロイ

`main` への push で Cloudflare Pages が自動ビルド＆デプロイ。
