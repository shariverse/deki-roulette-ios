# デキレーレット 機能仕様書

Web 版（https://roulette.basekeita.com/）の機能を、実装から洗い出してまとめた仕様書。
iOS 版・visionOS 版はこの仕様を元に移植しており、プラットフォーム差分は末尾の「iOS 版との対応」「visionOS 版との対応」に記す。

- Web 版の対象リビジョン: b7b3936（このリポジトリの履歴に残っている。Web 版のコードは iOS 版への移行時に削除した）
- 数値の定義元: `src/config.ts`、配色の定義元: `tailwind.config.ts`、文言の定義元: `src/i18n.ts`

---

## 1. 概要

### 1.1 コンセプト

「ルーレットで決めたことにしたい」場面で使う抽選ツール。回す前に当てたい項目を仕込んでおくと、
見た目はランダムに回りながら結果はその項目に止まる。人に画面を見せながら使う前提のため、
**仕込めることが画面上から一切分からない**ことを最優先の設計要件とする（§6）。

### 1.2 画面

| 画面 | 役割 | 日本語 URL | 英語 URL |
|---|---|---|---|
| ルーレット | 項目から 1 つを選ぶ | `/` | `/en/` |
| 順番決め | 項目をランダムに並べ替える | `/order/` | `/en/order/` |

2 画面は独立しており、項目リストや指定は共有しない。

### 1.3 非機能

- 状態は永続化しない。リロードすると初期項目に戻る。（iOS 版は項目リストだけ端末に保存する。§12）
- ネットワーク通信は行わない。外部スクリプトも読み込まない。
- ログイン・登録・課金は無い。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 項目 (Item) | ユーザが登録するラベル付きの要素。`id` と `label` を持つ（iOS 版は見た目も持つ。§4.7） |
| 印 (Mark) | 項目リストの行に出す指定の状態。`target`（当たり）/ `first`（先頭）/ `last`（末尾） |
| 当たり指定 | ルーレットで次のスピンの結果にする項目の指定 |
| 先頭・末尾指定 | 順番決めで 1 位・最下位にする項目の指定 |
| 演出中 (busy) | スピン中、または並べ替え結果を 1 件ずつ出している間（iOS 版の「スピンの演出」の停止のあとの余韻・紙吹雪・帯の登場演出は含めない。§5.5） |
| 伏せる (conceal) | 印を無条件に非表示にすること |

## 4. 共通機能: 項目リスト

両画面で共有する。見出し「項目」と件数 `現在数 / 24` を右上に表示する。

### 4.1 初期項目

| 画面 | 日本語 | 英語 |
|---|---|---|
| ルーレット | ラーメン、カレー、寿司、焼肉 | Pizza, Burger, Sushi, Tacos |
| 順番決め | A チーム、B チーム、C チーム、D チーム | Team A, Team B, Team C, Team D |

### 4.2 追加

- 入力欄と「追加」ボタン。Enter キー（フォーム送信）でも追加できる。
- 入力欄は `maxLength=20`。
- 追加時にラベルを**正規化**する: 連続する空白（改行含む）を半角スペース 1 つに潰し、前後の空白を落とし、先頭 20 文字で切る。
- 正規化後が空文字なら追加しない。
- 項目数が上限 (24) に達している間は、入力欄と追加ボタンを無効化し、「項目は 24 個までです」を表示する。
- 演出中は入力欄と追加ボタンを無効化する。
- 追加すると表示中の結果を消す（ルーレット: 結果ラベル、順番決め: 結果リスト）。iOS 版のルーレットは結果の帯と盤面の強調を消す（§5.3）。
- 項目 ID はランダム（`crypto.randomUUID`、非 secure context では時刻＋乱数）。同じラベルの重複登録は許す。
- iOS 版のみ: 入力に改行が含まれていれば行ごとに正規化して空行を除き、まとめて追加する（一括追加）。
  - 20 文字の制限は行ごとに掛ける。1 件ずつの正規化の規則は変えない。
  - 複数行が入っているときは追加ボタンの表示を「N 件追加」にする。
  - 上限 (24) を超える分は切り捨て、「項目は 24 個までです」で伝える（VoiceOver には同じ文言を読み上げる）。
  - 追加したあとも入力欄のフォーカスを保ち、続けて次の項目を入力できる。キーボードは下スワイプで閉じる。
  - 「使い方」の基本操作に、改行区切りで貼り付けるとまとめて追加できる旨を載せる。
  - 入力欄のプレースホルダーでも「項目を入力（改行で複数追加）」/ "Add items (one per line)" と示す。
- iOS 版のみ: 同じラベルの項目があるときは**警告だけ**を出す。追加・スピン・並べ替えは止めず、同名の項目を自動で消したりまとめたりしない。
  両画面で同じ規則・同じ見た目で、画面ごとの切り替えは持たない。
  - 「同名」は正規化後のラベルの完全一致。大文字小文字・全角半角の違いは別物として扱う。
  - リスト上の注意: 同名の項目がある行すべてのラベルの下に「⚠ 同じ名前の項目があります」/ "Duplicate name" を出す（補助テキストの色）。
    項目から毎回求めるので、1 件追加・一括追加・保存したリストの読み込み・保存データの復元・「元に戻す」のどの経路で入っても出て、
    消すか名前を変えるまで出たまま。演出中・結果表示中も出す。行の読み上げにも含める。
  - 追加時の確認: 追加するラベルが既存の項目と同名、または一括追加の行同士で同名なら、追加の前に
    「同じ名前の項目があります／このまま追加しますか？」を出す。「追加する」で同名の行も除かずに通常の追加と同じく追加し（上限 (24) を超える分は切り捨てる）、「やめる」で何も追加せず
    入力を残してフォーカスを戻す（Return で送信したときの末尾の改行は落とす）。同名でなければ確認なしで追加する。
    読み込み・復元・「元に戻す」では確認を出さない（リスト上の注意だけで伝える）。
  - 指定（§6）とは無関係に出す。同名の片方に指定が付いていても、注意の見た目・読み上げは同名の行すべてで同じにし、
    印（色見本）の位置・形・色は変えない。文言に「当たり」等の語は置かない。

### 4.3 削除

- 各行右端の「✕」ボタン。読み上げ名は「{ラベル} を削除」。
- 演出中は無効化する。
- 削除した項目に指定（当たり／先頭／末尾）が付いていれば、その指定も外す。
- 削除すると表示中の結果を消す。
- iOS 版のみ: 見出し行に「すべて削除」を置き、確認ダイアログを経て全件削除する。項目 0 件と演出中は出さない。指定と結果も消える。
- iOS 版のみ: 行を左にスワイプすると、右端に「削除」ボタンが現れる。押すと「✕」と同じく削除する。
  - 指が 20pt（`Config.swipeMinimumDistance`）動き、その時点で横が優勢なときだけスワイプとして扱う。縦や斜めはスクロールに譲る。
  - 行幅の半分（`Config.swipeDeleteRatio`）を越えて引いたら、指を離した時点でそのまま削除する。勢いだけでは削除しない。
    それ未満なら、離した勢いを足した位置が削除ボタンの半分を越えれば開いたまま止め、越えなければ閉じる。
  - 開いておくのは常に 1 行だけ。開いた行のタップで閉じる。演出が始まったら閉じ、演出中はスワイプできない。
  - 長押し（§6.1）は指が 10pt 動くと不成立になるので、スワイプしようとして指定することはない。長押しで指定が成立したあとに
    指を動かしても、その操作ではスワイプを始めない。削除ボタンの見た目は指定の有無で変えない。
  - 削除ボタンは読み上げから外す（VoiceOver では「✕」で同じ操作ができる）。`accessibilityAction` は置かない。
- iOS 版のみ: 「✕」かスワイプで削除した直後の 5 秒間、リストの下に「{ラベル} を削除しました　元に戻す」を出す。
  - 「元に戻す」で同じ `id` の項目を元の位置に戻す。指定（当たり／先頭／末尾）は復元しない。戻すと表示中の結果は消える。
  - スピン／並べ替えを始めたら閉じて取り消し不可にする。表示中に別の項目を削除したら直前の削除は確定して置き換える（多段 Undo は持たない）。
  - 元の位置が項目数を超えていれば末尾に戻す。同じ項目がすでにあるか上限 (24) に達していれば何もしない。
  - 表示と同じ文言を読み上げる（`aria-live` 相当）。文言に「当たり」等の語は置かない。

### 4.4 行の表示

- 左に 12px の丸い**色見本**（項目の並び順 i に対し `SLICE_COLORS[i % 10]`）、右にラベル（1 行、はみ出しは省略記号）。
- 色見本はルーレットのスライス色と一致する。順番決めにも同じ色を使う。
  iOS 版は件数によって末尾の色をずらす（§5.1、§12）。色見本も盤面と同じ関数で引くので、ずらした色でも一致する。
- iOS 版は項目ごとに色・絵文字を選べる（§4.7）。色の項目の色見本は選んだ色。絵文字の項目は色見本（自動の色）を残したまま、その右・ラベルの前に絵文字を出す。
- 行本体はボタン要素で、隠しジェスチャ（§6）の受け口。単純クリック／タップでは何も起きない。
- リストは最大高さ 320px でスクロールする。

### 4.5 状態メッセージ

| 条件 | 表示 |
|---|---|
| 項目 0 件 | 破線枠で「まずは項目を追加してください」 |
| 項目 1 件以下 | 赤字で「項目をあと少なくとも 2 つ追加してください」 |
| 24 件 | 「項目は 24 個までです」 |

### 4.6 名前を付けて保存したリスト（iOS 版のみ）

Web 版には無い。用途ごとの項目リスト（ランチの候補、チームのメンバー…）を名前を付けて保存し、呼び出せる。

- 見出し行の右端にメニュー（`…`）を置く。「このリストを保存」「保存したリストから読み込む」（保存済みの一覧をサブメニューで出す。無ければ「保存したリストはありません」）「保存したリストの管理」の 3 つと、区切り線をはさんで「色と絵文字を編集」（§4.7）。行本体のタップ・長押しの挙動（§6）は変えない。演出中はメニューを無効化する。
- 保存: 名前を入力するアラート（テキスト欄付き）を出す。名前は項目のラベルと同じ規則で空白を潰し、30 文字で切る。空なら保存しない（保存ボタンを無効化）。項目が 0 件のときは保存を選べない。
- 保存できるのは 20 セットまで。上限に達した状態で保存を選ぶと、管理画面から削除するよう案内するアラートだけを出す。
- 読み込み: 現在の項目を保存したリストの項目で置き換え、表示中の結果と当たり・先頭・末尾の指定を消す。確認は挟まない。
- 保存先はルーレットと順番決めで共通。片方で保存したリストをもう片方で読み込める。
- 保存するのは各リストの `id`・名前と、項目の `id`・`label`・見た目（色・絵文字。自動のときは書かない）だけ。当たり・先頭・末尾の指定は保存にも読み込みにも含めない。
- 管理画面（シート）: 保存したリストを名前と件数で一覧し、行をタップして名前を変更、スワイプまたは「編集」で削除する。読み込みは置かない。
- 永続化は `UserDefaults`（キー `savedLists`）に JSON で保存する。読めないときは空として扱う。読めたリストは名前を正規化し、名前が空・`id` が重複するものは落とし、項目は §4.2 と同じ規則で整える。

### 4.7 項目の見た目（iOS 版のみ）

Web 版には無い。項目ごとに「自動」「色」「絵文字」のどれか 1 つを見た目として選べる（併用はしない）。見た目だけの値で、抽選・指定・止まる位置・音・触覚の時刻には使わない。

- **自動**（既定）: 今までどおり並び順と件数から色を引く（§5.1、§12 の継ぎ目のずらしも含む）。
- **色**: スライスの 10 色（§9.1 の `SLICE_COLORS`）から 1 つ。盤面のスライス・行の色見本・結果の帯の枠・光彩「止まったスライスの色」・3D 表示・共有画像をその色で描く。ライトの外観で色見本などに暗い版を使う規則は自動の項目と同じ。選んだ色で隣り合うスライスや継ぎ目が同じ色になっても変えない（自動の項目の色も動かさない）。
- **絵文字**: 絵文字 1 文字（1 書記素）。色は自動のまま、ラベルの前に絵文字を出す。
  - 盤面（2D・3D・共有画像）: 「絵文字＋細い空白（U+2009）＋ラベル」。省略の上限（§5.1 の表）は絵文字ぶん 1 文字短くなる（10 / 7 / 5 文字なら、ラベルは 9 / 6 / 4 文字まで）。
  - 結果の帯（2D・3D・共有画像）: 全文の前に絵文字。
  - 項目リストの行（§4.4）: 「色見本＋絵文字＋ラベル」（色見本は自動の色のまま残し、印はこれまでどおり色見本で出す）。
  - 順番決めの結果の行（§7.2）: 順位の右・ラベルの前に絵文字。順番決めの共有画像（§7.3）: 「1. 🍣 ラベル」。
  - 読み上げ・結果のテキスト・共有の本文（`ResultText`）はラベルのまま（絵文字を入れない）。行の絵文字は読み上げから外す。
- **編集**: 項目リストの見出し行のメニュー（§4.6）の「色と絵文字を編集」でシートを開く（項目が 0 件のときは選べない。メニューと同じく演出中は無効で、結果表示中は開ける）。
  - 全項目の一覧（色見本・絵文字・ラベル・今の見た目の名前）から項目を選ぶと、その項目の編集画面に進む。10 色の円（VoiceOver は色の名前と選択中）・絵文字の入力欄・「自動に戻す」（自動のときは無効）を置く。色と絵文字は片方を選ぶともう片方が外れる。
  - 絵文字はキーボードで入力し、アプリ内の絵文字一覧は持たない。入力欄は**確定したとき**（Return・フォーカスが外れた・画面を離れた）だけ判定する（かな入力の変換「すし」→ 🍣 を途中で弾かないため）。
    前後の空白を落とした先頭の 1 書記素が絵文字ならそれにし、2 文字以上は先頭の 1 文字だけ残す。今の絵文字の後ろに足したときは足した絵文字に差し替える。
    絵文字でなければ前の値に戻し、欄の下に「絵文字を 1 文字だけ入力できます」と出して読み上げる。絵文字の項目で欄を空にして確定すると自動に戻る（色・自動の項目はそのまま）。
  - 絵文字として受け付けるのは、既定で絵文字表示の文字か、異体字セレクタ（U+FE0F）・肌色・ZWJ で絵文字表示にした並び（国旗は地域指示子 2 つ、数字・`#`・`*` はキーキャップ付きだけ）。文字表示の異体字セレクタ（U+FE0E）付き・肌色の修飾子だけ・国旗の片割れは受け付けない（`EmojiInput`）。
  - 見た目を変えても結果と指定は消さない。盤面・帯・共有画像はその場で新しい見た目になり、結果の出し直しの動きは起きない。
  - シートには項目（id・ラベル・見た目）だけを渡し、指定・印は出さない（§6）。行本体・スワイプ・色見本には入口を置かない。
- **保存**: 画面ごとの項目リスト（§12 の `ItemStore`）と名前を付けて保存したリスト（§4.6）に含める。項目の JSON に任意のキー `appearance` を足し、`{"kind": "color", "value": "<色の名前>"}` / `{"kind": "emoji", "value": "<絵文字>"}` で書く。
  色は並びの添字ではなく名前（`red` `orange` `yellow` `lime` `green` `cyan` `blue` `violet` `purple` `pink`）で持つ。自動のときはキーごと書かないので、見た目が入る前の保存データもそのまま読め、見た目の無い項目は自動になる。
  知らない種類・色・絵文字でない値・形の違う値は、項目を捨てずに自動として読む。見た目の入る前のアプリが新しいデータを読むと項目は読めるが、そのまま保存し直すと見た目は消える。
- 同名の注意（§4.2）はラベルだけで判定し、見た目は見ない。

## 5. ルーレット画面

### 5.1 盤面

- 320px（画面幅の 78% を上限）の正方形 SVG。中央固定の針（赤い下向き三角）が盤面の真上 (12 時) にある。
- 項目 i のスライスは角度 `[i·360/n, (i+1)·360/n)` を占め、12 時から**時計回り**に並ぶ。
- スライスの塗りは `SLICE_COLORS[i % 10]`、区切り線とラベルは地色 `#17111F`。
  盤面は環なので末尾のスライスは先頭と隣り合い、件数 n が `n % 10 == 1`（11 件・21 件）のときは継ぎ目が同じ色になる。
  iOS 版はこの件数のときだけ末尾の色をずらす（§12）。
- ラベルは半径の 62% の位置に放射方向に置き、左半分は 180 度返して上下逆さまにならないようにする。
- ラベルは項目数に応じて省略する:

| 項目数 | 最大表示文字数 | フォントサイズ |
|---|---|---|
| 〜5 | 10 | 13 |
| 6〜8 | 7 | 11 |
| 9〜 | 5 | 9 |

- iOS 版は色の項目を選んだ色で塗り、絵文字の項目は絵文字ぶん 1 文字短く省略してラベルの前に絵文字を出す（§4.7）。
- 項目 0 件: 無地の円盤。1 件: 全面 1 色にラベルを中央表示（スピンは不可）。
- 中央にハブ（暗色の円＋アイボリーの縁と芯）。
- iOS 版は横並び（`horizontalSizeClass == .regular`、主に iPad）で盤面を最大 480pt に広げる。線幅・縁・ハブは直径に比例させ、
  上の表の文字数と文字サイズは直径 320pt を基準に、それより大きい盤面では倍率の平方根ずつ緩める（§12）。

### 5.2 スピン

- 「スピン」ボタン。項目が 2 件以上かつスピン中でないときだけ有効。スピン中はラベルが「スピン中…」になる。
- 押した瞬間にフッターの「使い方」を自動的に閉じる（§6.4）。
- 回転角の計算（`useRoulette.spin`）:
  1. 当たり指定があればその項目の添字、無ければ一様乱数で添字を選ぶ。
  2. そのスライス内のランダムな角度 `raw` を決める。
  3. 針の下に来る盤面角は `(360 − R) mod 360` なので、`raw` に止めるための目標剰余 `desired = (360 − raw) mod 360` を求める。
  4. 現在の回転角との差 `delta` を 0〜360 で求め、10 度未満なら 1 周足す（ほとんど動かないスピンを避ける）。
  5. 周回数を 4〜8 周から乱数で選び、`next = current + 周回数·360 + delta` を累積回転角とする。
- 回転は CSS `transform: rotate()` のトランジション（4.5 秒、`SPIN_EASING`）。累積角を使うので常に同じ方向（時計回り）に回る。
- 完了は `transitionend` で検知する。バックグラウンドタブ等で発火しないときは 5.1 秒のタイマーで打ち切る。
- 結果はスピン開始時に確定しており（`pendingResult`）、完了時に表示する。
- iOS 版は盤面のフリックでも開始できる。フリックの強さは手順 5 の周回数にだけ反映し、止まる位置の計算は変えない（§12）。
  フリックした向きに回し、反時計回りでは手順 4 の `delta` を逆向きに測って `next = current − 周回数·360 − delta` とする（累積角が減る）。
  「スピン」ボタンは直前のフリックの向きで回す（§12）。ドラッグ中は盤面が指に追従し、指を離した角度を `current` としてスピンを始める（§12）。
  一定以上の勢い（角速度 240°/秒以上）でフリックしたときだけスピンを始め、それより弱く離したときは抽選せず、離した速さに応じて
  盤面が少しだけ（最大 60 度ほど）惰性で回ってから止まる。惰性で回る間も、針が境目を越えるたびに回転音と触覚を鳴らす（§12）。
  盤面は指を離した瞬間の速さで回り出し、そこから減速する（曲線の始点の傾きだけを変え、止まる位置は同じ。長さ・保険のタイマーも
  止まり際の焦らし（§5.5）が OFF のときはボタンと同じで、ON では焦らしの分だけ長くなるのもボタンと同じ。§5.5・§12）。
- iOS 版のみ: 設定の「スピンの演出」（既定はすべて ON）で、スピンに電飾・光の尾・パーティクル・効果音の演出が付き、止まり際に焦らしの動きが入る（§5.5）。
  止まる位置・結果は上の手順で開始時に決まったまま変えない。全体を OFF にしたときの動き・見た目・音は演出を付ける前のまま。

### 5.3 結果表示

- 盤面の下、高さ固定の領域に表示する。
  - 未スピン: 「スピンすると、ここに結果が出ます」
  - スピン中: 「スピン中…」
  - 完了後: 金色 (`gold`) の枠でラベルを強調表示。`animate-reveal` で現れる。
- 領域は `role="status" aria-live="polite"`。スクリーンリーダーには「結果は {ラベル} です」相当が伝わる。
- 項目の追加・削除・指定の変更で結果は消える。
- iOS 版は盤面の下の結果領域を持たない（未スピン・スピン中の案内も出さない。スピン中はボタンのラベルが「スピン中…」になる）。結果は下記の盤面の中心より下に重ねる帯と盤面の強調で見せ、読み上げは従来どおり「結果は {ラベル} です」をアナウンスする（§12）。
- iOS 版のみ: 結果があり演出が終わった後だけ、スピンボタンの下に幅広の「結果を共有」ボタンを出す（§7.3 と同じ見た目・同じ扱い）。「結果をコピー」は置かない（本文は共有シートの「コピー」で写せる）。
  - 共有は共有シート（`ShareLink`）に、結果の文の 1 行に空行を挟んでハッシュタグを 1 行足した本文を渡す（アプリ名の行は置かず、ハッシュタグで何のアプリか分かるようにする）:
    ```
    ルーレットで「ラーメン」に決まりました！

    #デキレーレット
    ```
    英語は `The wheel picked “Ramen”!` と `#DekiRoulette`。結果の文の型は `shareRouletteResult`（`%@` にラベル）、ハッシュタグは `shareHashtag`。
    App Store の URL（`Config.appStoreURL`）があるときだけ、ハッシュタグの次の行に付ける。未公開の間は nil で、リンクは付かない。
    本文に絵文字は入れない（項目の絵文字も入れない。§4.7）。「当たり」「必ず」等の語・指定の有無・項目リストも入れない（§6.5）。
  - iOS 版のみ: 共有シートには本文と一緒に結果の画像（PNG、1080×1080 px の正方形）を渡す。画像を本体にし本文を添えるので、X・LINE には画像と本文、Instagram には画像が届く。
    画像には 2D の盤面（止まったスライスの強調と針を含む）・結果の帯・アプリ名の文字だけを描く。項目リスト・印・指定の有無は載せず、「当たり」「必ず」等の語も置かない（§6.5）。
    画面のスクリーンショットではなく描き直すので、画面キャプチャ中に印を伏せる仕組み（§6.3）とは関わらない。3D 表示（§12）が ON でも 2D の盤面で描く。
    地は外観に依らず固定のダーク、アプリ名は白系の文字だけ（アイコンは置かない）。画像は結果が出て演出が終わった後に 1 回だけ描き、スピン中・結果が無いときは作らない。
    画像を作れなかったときは本文だけを共有する。
  - スピン中と結果が無いときはどちらも出さない。
- iOS 版は盤面上で針の下のスライスを強調する。結果が消えると強調も解ける（§12）。
- iOS 版のみ: 結果があり演出が終わった後だけ、盤面の中心より下（下半分）に帯を重ねて結果のラベルを全文で大きく出す（盤面のラベルは §5.1 の文字数で省略されるが、帯は `Config.maxLabelLength` まで省略しない）。結果の文字はこの 1 か所だけで、針の下には出さない。止まった位置は盤面の強調と帯の枠の色で示す。
  - 帯は回転しない層に置き、盤面が回っても指で動かしても文字は回らない。盤面・ハブ・止まったスライスより手前に描き、下半分のスライスとラベルを一部隠す。
  - 白系の地（`Theme.resultBandFill`）に盤面と同じ暗い文字（`resultBandInk`、4.5:1 以上）で、枠は止まったスライスの塗り（`sliceColor(in:at:)`。色の項目は選んだ色、§4.7）。絵文字の項目は全文の前に絵文字を付ける。`gold` / `flare` は使わない。
  - 寸法は `ResultBand`。盤面と同じく装飾扱いで Dynamic Type には追従せず、直径に比例させる（基準 320pt で 28pt、幅は直径の 72% まで）。収まらないときは 1 行のまま 0.5 倍まで縮め、それでも収まらなければ末尾を省略する。帯の中心は盤面の中心から半径の 40% 下に置き、中心のハブと重ねず、盤面のスライスの円からはみ出さない。
  - 出し直しはスピンごとで、`animate-reveal` 相当で現れる（`accessibilityReduceMotion` ではすぐ出す）。「スピンの演出」の停止の演出が ON のときは、これに登場演出（§5.5）を重ねる。指で盤面を動かしても出し直さない。スピン中と結果が無いときは出さない。
  - 帯は読み上げない（盤面と同じく `accessibilityHidden`）。結果は従来どおり読み上げで伝える。盤面のフリックを妨げないよう触れられない。
- iOS 版のみ: 「スピンの演出」の停止の演出が ON のときは、停止の瞬間のフラッシュ・帯の登場演出と、結果が出ている間の余韻（光がゆっくり脈打つ）が付く（§5.5）。
  紙吹雪は火花・紙吹雪が ON のときだけ（§5.5 の表）。結果の決まり方・帯の文字・読み上げは変えない。
  演出中（busy、§2）はスピンの停止で終わり、停止のあとの余韻・紙吹雪・帯の登場演出は含めない（結果が出たらすぐ項目の編集・次のスピンができる）。

### 5.4 当たり指定

- 行の長押し（§6.1）で、その項目を次のスピンの結果にする。もう一度長押しすると解除。
- 同時に指定できるのは 1 項目。別の項目を長押しすると指定が移る。
- 指定は何度スピンしても残る（解除されるまで毎回同じ結果になる）。
- 何も指定していないとき、結果は一様乱数。

### 5.5 スピンの演出（iOS 版のみ）

「スピン」ボタンや盤面のフリックで回したときに、派手な演出を付ける（Discussion #263。既定ですべて付け、要らない演出だけを設定で止められる。Discussion #310）。触っていて楽しいことが目的で、
抽選の仕組み（§5.2）とステルスの要件（§6）は変えない。

#### 設定

- 設定シートの「ルーレットの詳細設定」（光彩の色・3D 表示と同じ画面）に「スピンの演出」を置く。先頭に全体の ON / OFF（「演出を付ける」）、その下に演出ごとのトグルを 6 つ並べる。
  既定はすべて ON（全部入り）。どれも `UserDefaults` に Bool で保存し、未設定は ON として読む。以前の 5 択の保存値（`spinEffectStyle`）は読まない（移行しない）。
- 全体が OFF のときは、個別のトグルを無効の見た目（不透明度 0.5、押せない）にして選択は残し、何も付けない（動き・見た目・音は演出を付ける前のまま）。全体を ON に戻すと、残した選択で付ける。
- 判定は `SpinEffects`（`Core/`。6 つのフラグ）だけを見る。全体の ON / OFF を踏まえた値は `SpinEffects.effective(enabled:selected:)` で求める。

| 表示（日本語 / 英語） | 保存のキー | 付く演出 |
|---|---|---|
| 演出を付ける / Show effects | `spinEffects.enabled` | 全体。OFF なら下の 6 つに依らず何も付けない |
| 電飾 / Lights | `spinEffects.lights` | 外周の電飾・背景の光の脈動 |
| 光の尾・残像 / Light trails | `spinEffects.trails` | 光の尾・残像 |
| 火花・紙吹雪 / Sparks and confetti | `spinEffects.particles` | 針の先の火花・停止の瞬間の紙吹雪 |
| 止まり際の焦らし / Suspense before stopping | `spinEffects.tease` | 止まり際の焦らし（下記「焦らし」） |
| 停止の演出 / Stop flourish | `spinEffects.stopEffects` | 停止の瞬間のフラッシュ・針を大きく弾く・結果の帯の登場演出・結果表示中の余韻 |
| 演出の効果音 / Effect sounds | `spinEffects.sounds` | うなり・決まり音（「ルーレットの回転音」も ON のときだけ鳴る。トグルの下に注記を出す） |

- 回転音（クリック）・触覚・3D 表示は今までどおり別のトグルで、「スピンの演出」には含めない。
- 針を大きく弾く動きは停止の演出の単位に含める（停止の演出が OFF なら針の沈みは今までどおり 4pt。下記「各演出」）。背景の光の脈動は電飾の単位に含める。
- 演出中（busy、§2）は今までどおりスピンの停止（結果が出たとき）で終わる。停止のあとも続く余韻・紙吹雪・フラッシュ・電飾の点滅・
  帯の登場演出は演出中に含めず、項目の編集・長押し・次のスピンを止めない（次のスピン・結果が消えたら余韻・電飾の点滅と脈動・フラッシュは止まり、
  はじけた紙吹雪だけは最後まで落とす）。
- 保存のキーは出したあとは変えない（変えると保存済みの選択が読めず ON に戻る）。
- 3D 表示（§12）の ON / OFF に関わらず、2D・3D の両方で同じ演出を出す。

#### 場面

| 場面 | 出す演出 |
|---|---|
| 待機中（結果なし） | 電飾は弱く点けたまま流さない。ほかは出さない |
| スピン中 | 速さに連動する演出（電飾の流れ・光の尾・残像・針の先の火花・背景の光の脈動）と、うなりの効果音 |
| 止まり際 | 速さが落ちるにつれて電飾のテンポが落ち、光の尾・残像・火花が消える。焦らしの動きが入る |
| 停止の瞬間 | 電飾の全灯の点滅、紙吹雪、フラッシュ、針を大きく弾く、決まり音、帯の登場演出（それぞれのトグルが ON のときだけ。上の表） |
| 結果表示中 | 余韻: 止まったスライスの光彩と電飾がゆっくり脈打つ。次のスピン・結果が消えたとき・盤面を指で動かしたときに止める |
| 指で動かしている間 | 動かす速さに連動する演出（電飾の流れ・背景の光の脈動・光の尾・残像・火花）だけ。速く動かすほど光り、指を止めると約 0.5 秒で落ち着く。抽選しないので停止の演出・焦らし・効果音（うなり・決まり音）は出さない（回転音・触覚は今のまま）。結果が出ているときに動かすと、余韻などの停止の演出は止まる |
| 閾値未満で離した後の惰性 | 惰性の速さに連動する演出だけ（停止の演出・焦らし・効果音は出さない。回転音・触覚は今のまま）。惰性は離した角速度が 240°/秒未満（強さ約 0.33 未満）から減速するので、光の尾・残像（閾値 0.35）は出ず、実際に見えるのは電飾の流れと少しの火花 |

- 速さに連動する演出の強さは、回転の角速度から決める。補間中の角度は observable でないので、回転音・触覚と同じく、スピン（焦らしを含む）・惰性の曲線から
  時刻 → 角度・角速度を求める純粋関数を `Core/` に置き、`TimelineView` で毎フレーム引く。ドラッグ中は指が回した角度の変化から求める。
  角速度を 0〜1 の強さに写し（既定は 720°/秒で 1）、各演出はこの強さだけを見る。
- ドラッグ中の角速度は、フリックの判定（§12）と同じく直前 0.15 秒に指が盤面の中心のまわりを回った角度 ÷ 時間（中心から 24pt 以内に掛かる動きは数えない）で、
  指の点と点の間の揺れを時定数 0.08 秒の指数平滑でならす。指を止めると 0.15 秒で 0 に向かい、最後に指が動いてから 0.5 秒で止まり切ったとみなす
  （そこで毎フレームの描き直しも止める）。指を離したあとも、離した動きの残りは同じく 0.5 秒まで描き、スピン・惰性に移ったらその動きから引く（短い惰性が 0.5 秒より前に止まり切っても、離す前の指の動きの残りには戻らない）。
  演出中（スピン中）に触り始めたドラッグは盤面が追従しないので、演出も出さない。

#### 各演出（数値は既定値。実装の PR で調整し、判断ログに残す）

- **電飾**: 盤面の外周の縁（スライスの円の外側の暗い環）の上に 24 個のライトを 12 時から等間隔に並べる。ライトは回らない層に置き、点いた光の並び（3 個おきに明るい）が回転の向きに流れる。
  - 置き場所と寸法: 盤面の枠・直径・スライスの円の大きさは変えず、電球は縁の中に収める（基準直径 320pt で、電球の環はスライスの円の外 8pt、電球の半径 2.2pt で、
    電球の外端はスライスの円の外 10.2pt と縁の外周（外 11pt）の内側。直径に比例させる）。にじみは電球の外へ最大 5pt（スライスの円の外 15.2pt）まで広がり、
    縁の外にもはみ出すが、盤面の枠（スライスの円の外 16pt）は越えない。電飾が OFF のときは何も足さない。色は外観に依らず固定の暖かい白系（`#FFE7B0`）で、明るさを不透明度にして縁に重ねる。
  - 3D 表示（§12）: 2D と同じ数・位置・大きさの電球を、盤と同じ面の外周の縁の上（縁の上面から 0.8pt 浮かせる）に置く。盤と一緒に傾き・揺れるが回らない
    （2D の回らない層と同じ）。針・結果の帯より奥で、針の下の電球（12 時）は針に隠れる。明るさ・流れ・点滅・脈動は 2D と同じ関数・同じ時計から引き、
    2D と同じ時刻に同じ光り方にする（スピン・焦らし・惰性・指で動かしている間・停止の点滅・結果表示中の脈動・待機中・動きを減らす設定のすべて）。
    電球の色は 2D で縁に重ねた色と同じ色を不透明に塗る（3D の描画は線形の色空間で重ねるので、不透明度で重ねると 2D より明るく見えるため）。
    にじみは電球の後ろに放射状のグラデーションの板を、にじみの強さで広げ・濃くして重ねる。にじみは光の尾のにじみ（下記）と違って縁の外周で切らず、
    2D と同じく縁の外（盤の無い宙）にも最大 5pt はみ出す。盤面の枠の中に収まり、場面は枠より片側 15%（`Theme.Wheel3D.overscan`）広く描くので、傾けても切れない。
  - 流れ: 並びの位置は盤面の累積回転角 × 0.25（盤面の 1/4 の速さで同じ向きに流れる）。角速度に比例して流れ、止まり際は減速に合わせてテンポが落ち、止まれば止まる。
    指で動かしている間・惰性も同じく角度から流れる。速さの強さ（0〜1）に比例して、光の並びの明るさ（0.6〜1）とにじみを上げる。
  - 流れの速さの上限: 並びが 1 フレーム（1/60 秒）に進むのは電球 0.5 個までにする（盤面で約 1,800°/秒。スピンの回り始めや速いドラッグはこれを超える）。
    上限で流し切れなかった分（遅れ）は電球 1 個分（盤面で 60°）まで次のフレームに持ち越し、上限の範囲で追いつかせる。超える分は捨て、並びは盤面より遅れて流れる
    （上限を下回ったら遅れを取り戻し、遅れが無くなれば盤面の角度の変化と同じだけ進み、止まれば止まる。捨てた分は取り戻さないので、

  - 3D 表示（§12）: 2D と同じ形・同じ値・同じ時刻の丸い光を、盤と同じ面のハブの上面より手前・結果の帯と針より奥に置く（電飾の上に重ね、針には隠れる）。
    浮かせた分の遠近の広がりを打ち消し、正面から見て盤面の枠の外へ広げない。
- **結果の帯の登場演出**: 今の `reveal` に加えて、帯を小さい大きさからばねで少し行き過ぎて収まるように出す。帯の文字・寸法・色は変えない。
  - 帯の中心を軸に 0.6 倍から、ばね（長さ 0.45 秒、弾み 0.35）で 1 倍に収める。行き過ぎはいちばん大きいときで約 1.03 倍で、そのときも帯はハブに重ならず
    スライスの円からはみ出さない。出し直しは帯と同じくスピンごとで、結果を出したまま設定を変えても途中から小さくしない。
  - 結果を出したまま 2D と 3D を切り替えたときは、切り替えた先の盤面が帯を新しく出すので、今の現れ方（`reveal`）とこの登場演出だけがもう一度出る
    （停止の時刻の規則（下記の余韻）により、フラッシュ・紙吹雪・電飾の点滅は出さない）。
  - 3D 表示（§12）: 盤と同じ面に貼った帯の板を、2D と同じく帯の中心を軸に 0.6 倍から同じばねで 1 倍に収め、今の現れ方（`reveal`）と重ねる。
    結果を出したまま項目の見た目を変えて帯を焼き直したときは動かさない。
- **結果表示中の余韻**: 止まったスライスの光彩（色は「光彩の色」の設定のまま）を周期 2.4 秒でゆっくり脈打たせる。
  - 光彩の不透明度に 0.4〜1 の倍率を掛け、電飾の脈動と同じ周期・同じ位相にする（電飾の点滅が終わる停止の 0.9 秒後にいちばん弱く、その 1.2 秒後にいちばん強い）。
    停止の瞬間は約 0.9 倍で、縁取り・押し出し・前に出したままの拡大は変えない。
  - 次のスピン・結果が消えたとき・盤面を指で動かして強調を解いたときに止める（光彩も強調と一緒に消える）。
  - 描き直しは結果表示中だけで、毎フレームではなく 1 秒 20 回にする（電飾の脈動と同じ）。
  - 3D 表示（§12）: 止まったスライスの光彩を焼いた画像の板の不透明度に、2D と同じ倍率・同じ位相を掛ける（光彩の無い同じ面の板を上に重ね、スライスからはみ出した光彩だけを薄くする）。
    停止の演出が OFF なら今までどおり光彩ごと焼いた 1 枚だけにする。
  - 停止の時刻（電飾の点滅と脈動・フラッシュ・余韻・紙吹雪の基準）は 2D と 3D で同じ規則で持つ: 結果が出た瞬間の時刻にし、結果を出したまま盤面が画面に出たとき
    （2D と 3D を切り替えた・画面に戻った）は電飾の点滅の長さだけ前に止まったことにして脈動から始め、フラッシュと紙吹雪は出さない。指で強調を解いたら電飾と余韻は止め、
    フラッシュと紙吹雪は止めない。結果が消えたら捨てる。
- 演出の色は `Theme` に置き、`gold`（順番決めの 1 位とフォーカスリング専用）と `flare`（開始ボタン専用）は使わない。スライス色を使うときは
  `Theme.sliceColor(in:at:)` / `sliceAccent(in:at:)` で引く（スライスを指さない紙吹雪だけは固定の 10 色。上記）。足した色は `ThemeContrastTests` で検証する。

#### 焦らし

- 止まり際の焦らしが ON なら、スピンの止まり際に焦らしの動きを入れる。入れるかどうかと入り方は、そのトグルと乱数（注入できる `RandomNumberGenerator`）と
  最終角だけで決め、指定（`targetId`）の有無・止まるスライスが何かでは変えない（指定があってもなくても同じ規則で毎回入れる）。
- 入り方は次の 3 通りから乱数で等確率に選ぶ（既定）:
  1. ためらい: 止まるスライスに入る境目の手前（止まる角度が境目から遠いときは止まる角度の手前）でほとんど止まりそうになってから、ゆっくり進んで止まる角度を行き過ぎ、少し戻り過ぎてから止まる
  2. 戻りかけ: 同じところで一度戻ってから進み直し、止まる角度を少し行き過ぎてから戻って止まる（止まるスライスの中で止まりかけたときは、境目を越えて手前の隣のスライスまで戻ることがある）
  3. 行き過ぎ: 振り子のように、止まる角度を行き過ぎ → 戻り過ぎ → 少し行き過ぎてから止まる（行き過ぎで先の隣のスライスに入ることがある）

  どの入り方も、止まり際は止まる角度のまわりで折り返すたびに振れ幅が縮む（減衰する往復。行き過ぎで 2 往復）。
  焦らしの区間で出入りするのは止まるスライスの前後の隣のスライスまでで、隣の 1 つ先のスライスには入らない。
- 最終角（止まる累積角）は開始時に `RouletteMath.nextRotation` で決めたものから変えない。焦らしの分だけスピンが長くなり（既定は 4.5 秒に 2 秒を足して 6.5 秒）、
  完了の保険タイマーは焦らしを含めた長さの 0.6 秒後にする（7.1 秒）。延ばす 2 秒は入り方（ためらい・戻りかけ・行き過ぎ）・件数・最終角に依らず固定で、
  ボタンでもフリックでも同じ。
- 動きは区間をつないで作る。主の区間は今のスピンと同じ 4.5 秒・同じ曲線（フリックでは離した速さで回り出す曲線）で、止まり際の手前の角度まで回す。
  残りの 2 秒が焦らしの区間で、3 つの区間をつなぐ。曲線は振り子の揺れ（正弦波）に近い ease-in-out（`cubic-bezier(0.37, 0, 0.63, 1)`）。主の曲線の終わりと
  焦らしの区間の両端（折り返し）は速さが 0 なので、つなぎ目で角度も速さも飛ばない。振れ幅はスライス幅（360° ÷ 件数）と上限の小さい方で決め、
  狭いスライス（24 件で 15°）でも広いスライス（2 件で 180°）でも破綻させない。止まる角度のまわりの揺れは、折り返すたびに k = 0.4 倍に縮める:

  | 入り方 | 主の区間の行き先 | 焦らしの区間（2 秒） |
  |---|---|---|
  | ためらい | 止まりかける角度 h（境目の手前 a（スライス幅の 25% と 8° の小さい方）と、止まる角度の 10° 手前の、止まる角度に近い方） | 1 秒で止まる角度の w 先（スライス幅の 40% と 8° の小さい方）まで → 0.6 秒で k·w 手前まで戻り過ぎ → 0.4 秒で止まる角度まで |
  | 戻りかけ | 止まりかける角度 h | 0.5 秒で r（スライス幅の 50% と 7° の小さい方）戻り → 1.2 秒で進み直して止まる角度の k·w 先まで → 0.3 秒で止まる角度まで。h が止まるスライスの中なら、戻りで境目を越えて手前の隣のスライスに入ることがある。a + r はスライス幅の 75% 以下なので、手前の隣のスライスの始まりの境目は越えない |
  | 行き過ぎ | 止まる角度の o 先（スライス幅の 60% と 14° の小さい方） | 1 秒で止まる角度の k·o 手前まで戻り過ぎ → 0.6 秒で k²·o 先まで少し行き過ぎ → 0.4 秒で止まる角度まで |

  o・w はスライス幅未満なので、行き過ぎ・戻り過ぎで前後の隣のスライスには入ってもその次には入らない。
  件数が多い（スライスが狭い）ときは割合の方が小さくなり、振れ幅はスライス幅に合わせて縮む（例: 24 件（15°）で a = 3.75°・r = 7°・o = 9°・w = 6°、
  8 件（45°）で a = 8°・r = 7°・o = 14°・w = 8°）。焦らしの区間の速さは、いちばん速くなる条件（行き過ぎの最初の戻り過ぎ: 14° + 5.6° を 1 秒）でも
  30°/秒ほど（演出の強さ 0.05 = 36°/秒の手前）に収め、速さに連動する演出（光の尾・残像・うなり）は出ず、火花はごくわずか。

  境目は止まる角度の直前の境目（件数と最終角だけから求まる）。止まる角度が境目から遠い（広いスライスの奥で止まる）ときは、境目は主の区間で越え、
  止まる角度の 10° 手前で止まりかける（止まりかけてから大きく回り直さないよう、焦らしの区間で進む距離を 10° に抑える）。完了の保険は動きの長さから決める。振れ幅は件数と最終角の幾何だけで決め、乱数は入り方を選ぶ 1 回だけ引く。
  スライス 1 つ分も回らないほど短い回転（スピンでは起きない）は焦らしを入れずに同じ長さで回す。
- 回転音と触覚は焦らしを含めた動きから境目を越える時刻を求め、戻る向きに越えた境目も数える（往復で同じ境目を何度も越えれば、越えるたびに鳴らす）。2D と 3D の盤面は同じ時刻に同じ角度にする。
- フリックで始めたスピンにも同じ規則で入れる（回り出しは離した速さのまま）。惰性（抽選しない）と `accessibilityReduceMotion`（回さない）には入れない。
- 乱数は 1 つの取得元（`RouletteModel.randomSource`）から、止まる項目 → 止まる位置と周回数 → 焦らしの入り方の順に引く。指定があるときも止まる項目の乱数は
  引いて捨てるので、同じ乱数の列なら指定の有無に依らず同じ動き（同じ区間の列・同じ境目の時刻）になる。
- 盤面は区間の列をそのまま補間する（`SpinPathAnimation`。経過時間ごとに角度の進み具合 `(角度 − 開始角) ÷ (最終角 − 開始角)` を引く）。2D の盤面と 3D の盤は
  同じアニメーションを受けるので同じ時刻に同じ角度になり、電飾など速さに連動する演出も同じ区間の列から角度・角速度を引く。焦らしが OFF の動きは今の 1 本の曲線のまま補間する。

#### 効果音

- 設定の「効果音」が ON のときだけ鳴らす（OFF なら回転音と同じく鳴らさない）。`AVAudioSession` は `.ambient` のまま（消音スイッチに従い、他アプリの音を止めない）。
- うなり（ドラムロール）: 抽選したスピン（ボタン・フリック）の間、回転の速さに合わせて音量・テンポ・ピッチを変えながら流し、止まり際に消える。回転音（クリック）より小さくする。
  - 1 打ち（0.12 秒）の音源を、打つ時刻ごとに並べる。各時刻の強さ（§5.5「場面」の角速度 → 0〜1。720°/秒で 1）から、次の打ちまでの間隔
    （強さ 1 で 0.055 秒 = 1 秒に約 18 打ち、0 に近づくほど 0.16 秒）・音量（強さ 0.05 以下（36°/秒以下）は打たず、そこから強さ 1 で最大まで比例）・
    ピッチ（再生の速さ。強さ 0 で 0.85 倍、1 で 1.15 倍）を決める（`SpinHum`）。1 打ちおきに 0.8 倍に弱めてロールの左右の手の強弱を付ける。
  - 速い序盤は詰まった打ちがつながってうなりになり、減速につれてまばらで小さく低くなり、止まる前に消える（既定のスピンでは 3〜4 秒あたりで消える）。
    焦らしの区間は強さが下限に届かないので鳴らない。
  - 再生の音量は `Config.humGain`（0.35。クリックは 0.7）。回転音と同じく、開始時に動き（焦らしを含む区間の列）から打つ時刻を求めて 1 本の波形に焼いてから流す
    （焼き込みはメインスレッドの外で行い、回転音・触覚の時刻を遅らせない。焼いた分の遅れは頭を切り落として盤面とそろえる）。
  - 結果が出たら止め（決まり音と重ねない）、次のスピンでは差し替え、画面を離れたら止める。
  - 指で動かしている間と惰性（抽選しない）では鳴らさない。`accessibilityReduceMotion` では盤面が回らないので鳴らさない。演出の効果音が OFF なら鳴らさず、音源も読み込まない。
  - 指定の有無・結果のラベルでは変えない（同じ動きなら同じ音）。
- 決まり音（チャイム）: 抽選したスピン（ボタン・フリック）が止まって結果が出た瞬間（完了の保険タイマーで止まったときも同じ）に、短い音を 1 回鳴らす。
  ド・ミ・ソ（C6・E6・G6）を 0.09 秒ずつずらして上がるアルペジオで、1 音は減衰する正弦波に 2・3 倍音を足したベルの音色、全体で 0.9 秒。
  音源は最大振幅 0.8 で書き出し（クリップしない）、再生の音量は `Config.chimeGain`（0.5）。回転音とは別に鳴らすので、クリックの最後の音と重なってよく、
  回転音を止めたり差し替えたりしない。惰性（抽選しない）では鳴らさない。`accessibilityReduceMotion` でも鳴らす。
  鳴らすかどうかは「スピンの演出」の演出の効果音・「効果音」・止まった動き（スピンか惰性か）だけで決め（`StopChime.plays`）、指定の有無・結果のラベルでは変えない。
  演出の効果音が OFF のときは鳴らさず、音源も読み込まない。
- 音源は外部素材を使わず、`scripts/` の Swift スクリプトで合成して `Resources/Sounds/` に書き出す（`make-click-sound.swift` と同じ作り。形式は 16bit / 44.1kHz / モノラルの WAV）。決まり音は `scripts/make-chime-sound.swift` が `chime.wav` に書き出す（乱数を使わず、同じスクリプトからは同じバイト列になる）。
  うなりの 1 打ちは `scripts/make-drumroll-sound.swift` が `drumroll.wav` に書き出す（響き線に当たる丸めたノイズ・音程が少し下がる胴鳴り・低い芯。ノイズは固定の種から作るので、同じスクリプトからは同じバイト列になる）。
- 音源（決まり音・うなり）は、画面が出たとき・画面を出したまま「スピンの演出」を変えたとき・「効果音」を OFF から ON にしたときに先読みする（最初のスピン・停止で読み込みを待たない）。
  別のタブにいる間は読まず、画面に戻ったときに読む。

#### ステルス・アクセシビリティ・共有画像

- 演出・焦らし・効果音の View と関数には指定（`targetId`）・印を渡さない。結果で変えるのは止まったスライス（`SpinOutcome`）を見る余韻の光彩だけ。
  設定と演出の文言に「当たり」「必ず」等の語を置かない（§6.5）。
- 演出は読み上げない（`accessibilityHidden`）。触れられない層に置き、盤面のフリックを妨げない。
- `accessibilityReduceMotion` では残像・光の尾・パーティクル・フラッシュ・電飾の流れと全灯の点滅・電飾と光彩の余韻の脈動・背景の脈動・焦らし・帯の登場演出・針を大きく弾く動きを出さない（§10）。
  電飾は点けたまま動かさず、停止の強調は今の最小限の表示のまま。スピンが回らないのでうなりは鳴らさず、決まり音は鳴らす。
- 演出の描画で回転音・触覚の時刻を乱さない。
- 共有画像（§5.3）には演出を載せない（画像は今のまま）。

## 6. 隠し操作（ステルス）の仕様

以下は仕様であり、削ったり戻したりしない。

### 6.1 ジェスチャ

- 指定は行本体の**長押し (600ms) のみ**。専用ボタン・ツールチップ・メニューは置かない。
- ポインタ: `pointerdown` から 600ms 押し続けたら発火。`pointerup` / `pointerleave` / `pointercancel` で取り消し。
- キーボード: 行にフォーカスして Enter またはスペースを押し続け、OS のキーリピート (`KeyboardEvent.repeat`) が始まった最初のイベントで 1 回だけ発火。単押しでは反応しない。
- 長押し中のコンテキストメニュー・テキスト選択のコールアウト (`-webkit-touch-callout`) は抑止する。
- 演出中は長押しを受け付けない。

### 6.2 印の見え方

- 指定中の行は色見本の**塗りを抜いてリング**（内側 2px の枝）にするだけ。位置・大きさは変えない。
- 末尾指定 (`last`) だけ、リングの中心に 2px の点を置いて先頭と見分けられるようにする。
- 指定中の行は枠線が 1 段明るくなる（`ink-700` → `ink-500`）。
- 印に専用色は使わず、その行の色見本の色をそのまま使う。

### 6.3 印を出す条件

印は次の**すべて**を満たすときだけ表示する。

1. 伏せていない（`concealMarks` が偽）。
   - ルーレット: スピン中は伏せる。
   - 順番決め: 並べ替え中と**結果表示中**は伏せる。
2. 次のいずれか:
   - リストにポインタが乗っている、またはリスト内の要素がフォーカスを持っている。
   - 長押しで指定を変えた直後 1.6 秒以内。
3. iOS 版のみ: 画面がキャプチャ（画面収録・AirPlay ミラーリング・QuickTime への出力）されていない。
   - キャプチャ中は押していても指定直後でも印を出さない。長押しによる指定の切り替え自体は動く（印が見えないだけで、操作は通る）。
   - キャプチャ中であることは画面本文に表示しない。説明は「使い方」の隠し操作の項にだけ置く（§12）。

印を伏せている行では `aria-pressed` を付けず、先頭／末尾のスクリーンリーダー向けラベルも出さない。DOM やアクセシビリティツリーに指定先が残らないようにする。

### 6.4 説明の自動閉じ

- 隠し操作の説明はフッターの「使い方」折りたたみ内にのみ置く。
- スピン／並べ替えを開始した瞬間に、開いていた「使い方」を閉じる。

### 6.5 文言の制約

- 画面本文（折りたたみの外）と meta 情報には「当たり」「必ず」など、仕込みの内容を示唆する語を置かない。
- 英語版の `<title>` / `<h1>` は一般語 (Roulette / Random Order) のみ。ブランド名「デキレーレット」は日本語版の `<title>` / `<h1>` と、英語版の description / JSON-LD `alternateName` にだけ置く。

## 7. 順番決め画面

### 7.1 並べ替え

- 「並べ替え」ボタン。項目が 2 件以上かつ演出中でないときだけ有効。演出中はラベルが「並べ替え中…」。
- 押した瞬間に「使い方」を自動的に閉じる。
- 並び順の決定（`shuffle.arrange`）:
  1. Fisher-Yates で一様にシャッフルする。乱数は `crypto.getRandomValues`。剰余の偏りを避けるため、範囲を割り切れる上限を超えた値は捨てて引き直す。
  2. 先頭指定があれば、その項目を添字 0 の項目と入れ替える。
  3. 末尾指定があれば、その項目を最後の項目と入れ替える。
- 「条件を満たすまで引き直す」方式は採らない（指定以外の並びに偏りが出るため）。指定以外の並びは常に一様。

### 7.2 結果表示

- 結果は順位付きリスト。1 位は金色 (`gold`) の枠と文字、以降は通常色。順位は等幅数字で右寄せ。読み上げは「{n} 番目」。
- 各行は `animate-reveal` に `index × 160ms` の遅延を掛けて 1 件ずつ現れる。全件そろうまで先の順位が読めないようにするための演出。
- 演出中 (`revealing`) は `(n − 1) × 160 + 360` ms 続く。この間は並べ替えボタン・追加・削除・長押しを無効化する。
- 未並べ替え時は破線枠で「並べ替えると、ここに順番が出ます」。演出開始直後で結果が無い状態は「並べ替え中…」。
- 領域は `role="status" aria-live="polite"`。
- 項目の追加・削除・指定の変更で結果は消える。

### 7.3 結果のコピー・共有

- 結果があり演出が終わった後だけ「結果をコピー」ボタンを表示する。
- クリップボードに次の形式で書き込む（改行区切り）:
  ```
  1. A チーム
  2. C チーム
  3. B チーム
  ```
- 成功したら 1.8 秒間ラベルを「コピーしました」に変える。失敗（権限拒否等）したら何も変えない。
- 並べ替え直すと「コピーしました」はリセットされる（どの結果をコピーしたかで判定する）。
- iOS 版は「結果をコピー」を持たない（§12）。代わりに結果があり演出が終わった後だけ、並べ替えボタンの下に幅広の「結果を共有」ボタンを置き、共有シート（`ShareLink`）に見出し「順番が決まりました！」（英語は `The order is set!`。`shareOrderHeading`）の下に上の形式の並びを置き、空行を挟んでハッシュタグを 1 行足した本文を渡す（本文だけを写したいときは共有シートの「コピー」を使う。App Store の URL の扱いは §5.3 と同じ）:
  ```
  順番が決まりました！
  1. A チーム
  2. C チーム
  3. B チーム

  #デキレーレット
  ```
- iOS 版のみ: 「結果を共有」は横幅いっぱい（上限 320pt）の、地を塗らない枠線（`ink600`）のカプセルで、文字は `ivory`、共有のアイコン付き。
  高さは 46pt（タップ領域 44pt を満たす。`Theme.Layout.resultActionsHeight`）で両画面とも同じ。開始ボタン（`flare` の塗りと光彩）より控えめにして主従を保ち、`flare` / `gold` は使わない。
  結果が出ても弾ませる・光らせる・共有シートを自動で開くなどの促しはしない（ボタンが出るだけ）。読み上げの名前は「結果を共有」。
- iOS 版のみ: 共有シートには本文と一緒に結果の画像（PNG、1080×1080 px の正方形）を渡す（§5.3 と同じ経路・同じ扱い）。
  画像には順位のカード（「1. ラベル」の並び。絵文字の項目は「1. 🍣 ラベル」で、本文には絵文字を入れない（§4.7）。1 位は `gold`、他は本文の色）とアプリ名の文字だけを描く。行は 10 行まで置き、超えるときは 9 件を並べて最後の行を「ほか M 件」にする。長いラベルは末尾を省略する。
  項目リスト・印・先頭・末尾の指定は載せない。画像は結果が出て演出が終わった後に 1 回だけ描き、並べ替え直すと作り直す。画像を作れなかったときは本文だけを共有する。
- Web 版でコピーする本文、iOS 版で共有する本文と画像には結果の並びとハッシュタグ（画像はアプリ名）だけを載せ、「当たり」「必ず」等の語や指定の有無を示す情報は含めない（§6.5）。

### 7.4 先頭・末尾指定

- 行の長押しのたびに **先頭 → 末尾 → 解除** と切り替わる。
  - 未指定の項目を長押し: その項目が先頭になる。すでに別の先頭があれば、その指定は外れる。
  - 先頭の項目を長押し: 先頭が外れ、その項目が末尾になる。すでに別の末尾があれば、その指定は外れる。
  - 末尾の項目を長押し: 末尾が外れる。
- 先頭と末尾はそれぞれ 1 項目まで。同じ項目が両方になることはない。
- 印の見え方・伏せ方はルーレットと同じ（§6.2, §6.3）。結果表示中も伏せる。

## 10. アクセシビリティとモーション

- `prefers-reduced-motion: reduce` のとき:
  - すべてのアニメーション／トランジションを実質 0 にする。
  - スピンは 320ms 後に完了扱いにする。
  - 順番の結果は遅延なしに一度に出し、演出は 200ms で終わる。
- 結果領域は `aria-live="polite"`。
- スピン中のボタンは `aria-busy`。
- 削除ボタンに「{ラベル} を削除」の読み上げ名。
- フォーカスリングは `gold` 2px。
- 指定中の行は、印が見えているときだけ `aria-pressed="true"` と先頭／末尾のテキストを付ける（§6.3）。
- iOS 版は触覚フィードバックを持つ（§12）。`accessibilityReduceMotion` のときはスピン中と順番決めの連続的な触覚を鳴らさず、開始と結果だけにする（指で盤面を動かしている間の境目は鳴らす）。
- iOS 版の 3D 表示（§12）は、`accessibilityReduceMotion` のとき盤を傾けず揺らさない（正面に置き、端末の姿勢も読まない）。停止時の押し出しと針の跳ねも 2D と同じく省く。
- iOS 版の「スピンの演出」（§5.5）は、`accessibilityReduceMotion` のとき残像・光の尾・パーティクル・フラッシュ・電飾の流れと全灯の点滅・脈動（電飾・光彩の余韻）・焦らし・帯の登場演出を出さない（電飾は点けたまま動かさない。停止の強調は今の最小限の表示のまま。うなりは鳴らさず、決まり音は鳴らす）。
  フラッシュは光過敏に配慮し、どの設定でも 1 秒に 3 回未満・不透明度 0.25 以下にする。演出は読み上げない。

iOS 版は Dynamic Type（文字サイズ）にも追従する（Web 版はブラウザの文字サイズ設定に依る）。詳細は §12。

- 文字はすべてテキストスタイル（`.largeTitle` / `.body` など）か `@ScaledMetric` で指定し、固定 pt を使わない。盤面（§5.1）だけは装飾として例外で、追従させない。結果は盤面の中心より下に重ねる帯（§5.3）と読み上げで伝える。帯は盤面の一部として盤面の直径に比例させ、文字サイズの設定には追従させない（大きな文字の利用者には、読み上げと「結果を共有」で全文を渡す）。
- タッチ領域は 44×44pt 以上（削除ボタンは見た目を変えず押せる範囲だけ広げる）。
- アクセシビリティサイズ（`accessibility1` 以上）では、項目リストと順番の結果行のラベルを 2 行まで許し、両画面の「結果を共有」（§5.3・§7.3）の固定高さを最小高さに緩め、ボタンの文字を省略せず 2 行まで折り返す。
- 項目リストの追加フォーム（§4.2）は、入力欄に十分な幅を確保できないとき（大きい文字や狭い画面）に縦積みにする。
- 印（§6.2）の 12pt とリングの線幅 2pt は文字サイズに依らず変えない（大きくすると印が目立つ）。

## 11. Web 固有の仕様

iOS 版には対応物が無い、または OS が代替する項目。

### 11.1 言語と URL

- 表示言語もページも **URL だけ**で決まる (`localeFromPath` / `pageFromPath`)。`navigator.language` は表示の決定に使わない。
- 各ページは自身への `canonical` と `ja` / `en` / `x-default` の `hreflang` を持つ。`x-default` は日本語版。
- 言語やページを増やすときの変更箇所: `i18n.ts` (`LOCALES` / `PAGE_PATHS` / `translations` / `PAGES` / `pageFromPath`)、エントリ HTML、`vite.config.ts` の `input`、各ページの `hreflang`、`public/sitemap.xml`、`scripts/prerender.mjs` の `PAGES`。

### 11.2 プリレンダリング

- ビルド時に React を静的 HTML へ焼き込み、`#root` に入れる。JS 実行前から画面のテキストが HTML にある。
- 焼き込むのは画面に出ている文言だけ。`details` は閉じたまま、`aria-pressed` も出力に含めない。
- 誘導リンク (`LocaleNotice`) はマウント後に描画する。
- `main.tsx` は `#root` の中身の有無で hydrate と初回描画を選ぶ。

### 11.3 SEO・メタ情報

| ページ | `<title>` | `<h1>` |
|---|---|---|
| `/` | デキレーレット｜無料で使えるインチキルーレットアプリ | デキレーレット |
| `/order/` | 順番決め｜無料のランダム並べ替えツール｜デキレーレット | 順番決め |
| `/en/` | 一般語のみ（Roulette / Free） | Roulette |
| `/en/order/` | 一般語のみ（Random Order / Free） | Random Order |

- OGP / Twitter カード、JSON-LD (`WebApplication`)。`public/og.png` は盤面だけの中立な絵。
- `public/robots.txt` / `public/sitemap.xml`（4 URL、`xhtml:link` で言語対応）。

### 11.4 セキュリティヘッダ

`public/_headers` に CSP 等を定義し、Cloudflare の静的アセット配信が適用する。外部スクリプト追加時は `script-src` / `connect-src` を更新する。

### 11.5 デプロイ

`main` への push で Cloudflare Pages が自動ビルド＆デプロイ。

## 13. visionOS 版との対応

iOS 版との差分。対応バージョンは iOS 17.0 以上 / visionOS 26.0 以上（`sensoryFeedback` が visionOS 26.0 以降のため）。

| 項目 | iOS 版 | visionOS 版 | 備考 |
|---|---|---|---|
| 画面キャプチャの検知（§6.3、§12） | `UIScreen.isCaptured` と `UIScreen.capturedDidChangeNotification` | `UIWindowScene.traitCollection.sceneCaptureState` と `UITraitSceneCaptureState` の購読（`registerForTraitChanges`） | visionOS には `UIScreen` も変化の通知も無いため。通知の代わりに、trait の変化に加えてアプリがアクティブに戻ったときにも読み直す（`DekiRouletteApp` の `scenePhase`。収録中にアプリへ戻ったケースを拾う）。判定の意味（どれか 1 つでもキャプチャされていれば伏せる）と、`ScreenCaptureMonitor` を `Environment` で配る構成は両方同じ |
| ソフトウェアキーボード | スクロールで閉じる（`scrollDismissesKeyboard(.interactively)`、`PageFrame`） | ソフトウェアキーボードが無いので付けない | 入力の扱い自体（Return で追加してフォーカスを保つ、改行区切りの一括追加。§4.2、§12）は同じ |
| 触覚フィードバック（§12） | `sensoryFeedback` で鳴らす | `sensoryFeedback` は呼べるが、Vision Pro に触覚のハードウェアが無いため効果は無い | 設定の「触覚フィードバック」を含む共通コードはそのまま置く（効果が出ないだけ）。回転音と見た目の演出は iOS と同じ |
| 3D 表示の傾き・揺れ（§12） | `CMMotionManager.deviceMotion` で端末の姿勢を読む | 姿勢を読めない（`isDeviceMotionAvailable` が false）ので、盤は傾かず正面のまま | 揺れは見た目だけなので、抽選結果・止まる位置・触覚・回転音に影響しないという前提は両方同じ |
| アプリアイコン（§12） | Icon Composer の `.icon`（`DekiRoulette/Resources/AppIcon.icon`。代替アイコンも `<名前>.icon`）をそのまま使う | 同じ絵を層に分けた `Assets.xcassets/AppIcon.solidimagestack`（`Front` = 盤面と針、`Back` = 背景）を使う | `.icon` は visionOS に適用されない（Xcode が「適用できる visionOS のアイコンが無い」と警告し、アイコン無しのアプリになる）ため、`scripts/make-icon.swift` が `.icon` と同じ絵からスタックを書き出す。アイコンの選択（`ASSETCATALOG_COMPILER_APPICON_NAME: AppIcon`）は両方そのままで、iOS は `.icon`、visionOS はスタックが選ばれる |
| 設定シートの「アプリアイコン」（代替アイコンの切替。§12） | 既定のほかに代替アイコン 4 つを切り替えられる | 項目を出さない | 代替アイコンの API（`UIApplication.supportsAlternateIcons` / `setAlternateIconName(_:)` / `alternateIconName`）が visionOS に無いため、`UIApplicationIconSource` が非対応として振る舞う（`AppIconModel.isSupported` が偽になる）。ビルド設定でも visionOS には代替アイコンの名前を渡さない（`project.yml` の `ASSETCATALOG_COMPILER_ALTERNATE_APPICON_NAMES[sdk=xr*]`。渡すと actool が警告する） |
| スピンの演出（§5.5） | 2D・3D の両方で出す | iOS と同じ演出・焦らし・効果音（うなり・決まり音）を出す | 演出に使う SceneKit・SwiftUI・AVFAudio の API は visionOS でもビルドできるものに限り、`#if os(visionOS)` の分岐は持たない。触覚が無いので演出の手応えは見た目と音だけになる。3D の盤は姿勢を読めないので傾かないが、電飾・光の尾・粒子・フラッシュ・余韻・帯の登場演出は同じ規則で出る。低電力モードの判定（`ProcessInfo.isLowPowerModeEnabled`）は同じ |
| タブ（§12） | 画面下部のタブバー（`UITabBarAppearance` で外観を調整） | システム標準の左端の縦型バー | 同じ `TabView` の 2 タブ。`UITabBarAppearance` による調整は iOS のタブバー向け |
